# P32 双臂机器人策略在协同与交接上失败（Bimanual robot policies fail on coordination and handover）

## 一句话陈述

通过模仿学习、强化学习或 VLA 训练的双臂与灵巧手机器人策略，难以可靠完成紧密协同的双臂任务、臂间交接和人到机器人交接，部分基准在无噪声仿真中也是如此。表现较好的策略依赖完美点云、仿真器状态，或对交接对象的手和物体有完美感知。一旦换成真实感知，或从仿真迁移到真实环境，这些策略就会大幅失效。核查之后真正留下的部分更窄：反应式交接策略需要从真实 RGB-D 跟踪器得到遮挡下低延迟的手-物体 3D 状态，而目前的基准把这个状态当作真值直接提供。

## 基准证据

- TWIN/RLBench2 的 "handover an item" 任务上，ACT、RVT-LF 和 PerAct-LF 的成功率都是 0%，PerAct2 为 11%。13 个任务的平均成功率在 5.9% 到 17.5% 之间（758）。
- HGen-Bench 的 Handover and Storage 任务上，DP 和 DP3 的成功率都是 0%（469）。
- RoboTwin 的 Dual Shoes Place 任务成功率最高只有 12.0%；真实平台上的 Dual Bottle Pick Hard 为 11/50（1160）。
- RoboTwin 2.0 从 Easy 到 Hard，平均成功率的变化为：ACT 29.7% 到 1.7%，DP 28.0% 到 0.6%，DP3 55.2% 到 5.0%（1176）。
- BiGym 的 stack_blocks 任务上，七种算法全部为 0%；所有算法中最好的平均成功率是 46.3%（1163）。

## 为什么长期存在

记录给出的根本原因是：协同和交接都需要精确而及时的 3D 状态，包括两条手臂、物体和对方的手。基准用完美的仿真器状态提供这些信息，但真实世界里，在遮挡下感知这些状态还做不到。此外，协同示范数据本身稀缺，而且噪声大。尝试过的方法有大规模模仿学习（ACT、Diffusion Policy、DP3、RDT、Pi0）、LLM 生成的仿真数据（DP3 的收益到一定程度后不再增长）、域随机化、多任务预训练、主动视角感知、力觉（只带来小幅提升）、人工核验数据，以及人类视频联合训练和混合专家策略。协同和交接任务上的成功率依然偏低。从记录本身来看，策略侧拿到的是"免费"的真值状态，感知侧又少有人把它当作策略的输入来评估，这块交界地带一直没有人负责。

## 2025-2026 最新进展

证据侦察员的判断是 still_unsolved=YES，但问题的重心已经移动。在干净仿真中，协同与交接的成绩明显上升：Co-VLA 在 RoboTwin 2.0 Easy 上平均达到 82%（pi0 为 76%），Handover Block 达到 91%（pi0 为 64%）；M3 把干净设置的平均成功率从 41.0% 提到 62.7%，Handover Block 从 27% 提到 74%。在域随机化设置下，P32 描述的崩溃依然存在：Co-VLA 在 Hard 上平均只有 22%，Handover Block 只有 12%；M3 在 Clean2Rand 设置下只有 15.1%。真实双臂平台上，Co-VLA 在分布内的交接成功率为 73%，分布外只有 13% 到 27%。BiCoord 报告，DP、RDT、Pi0 和 OpenVLA-OFT 在长时程、双臂紧耦合的任务上都表现吃力。DexH2R 从 Easy 到 Hard 的成功率变化为：MotionNet 71.1% 到 26.6%，DP 39.4% 到 8.3%，DP3 66.3% 到 27.1%；作者把原因归于遮挡、缺少显式 3D 信息，以及对鲁棒分割的依赖。侦察员的总结是：干净仿真已经基本被带协同先验的大型 VLA 解决，而在真实感知和杂乱场景下，成功率仍只有约 10% 到 25%。

## 怀疑者结论

- solved 视角：未驳倒，4 分。决定性理由是记录里的仿真数字已经过时。Motus（arXiv 2512.13030，verified）在 RoboTwin 2.0 上干净设置为 88.66%，随机化设置为 87.02%；Riemann-1.0（arXiv 2608.27033，verified）报告平均 94.3%。不过，真实世界中的长时程耦合协同（BiCoord、DuoBench）和动态人到机器人交接仍然薄弱。改述：臂间协同已接近饱和，剩下的是对人类交接对象的低延迟、抗遮挡 4D 手-物体跟踪，以及在感知状态而非真值状态上评估策略的基准。
- artifact 视角：驳倒，3 分。决定性理由有三点：证据主要来自基准论文报告的自家 baseline，来源集中在少数谱系；在线 RoboTwin 2.0 排行榜上，ME-Dex-1.0 的 Handover Mic 达到 98/98，GigaBrain-0.7 达到 100/100；1533 是跟踪挑战报告，并不能支持关于双臂策略的论断。改述：这是"面向交接的感知缺口"，不是"协同策略缺口"；真实双臂基准的成功率仍只有约 24.4%（RoboDojo-real）。
- rq 视角：未驳倒，6 分。决定性理由是：去掉数据和规模化那部分之后，仍留下一个顶会级的问题——跟踪器应当以什么形式把手-物体状态、不确定性和延迟交给反应式策略，以及能否用与任务挂钩的指标取代 MPJPE 和 ADD-S，来预测下游交接的成功率。改述：研究"跟踪器到策略的接口"，并在真实而非高斯分布的感知误差下进行评估。

统计：驳倒数 1，平均分 4.3，结论 survives=true。

## 小实验室可行性与研究问题

worth_pursuing 为 MAYBE。分析者的理由是：P32 原始表述中的策略侧已被大模型推到接近饱和，小实验室无法竞争；可行的贡献在感知侧，即在公开数据上、在仿真里测量并设计跟踪器到策略的接口，最多再借一台机械臂做小规模真实验证。

研究问题 1：当人到机器人交接策略的输入从仿真真值换成真实 RGB-D 跟踪器的输出时，成功率会损失多少？损失分别来自哪些误差性质（结构化遮挡丢失、时间相关漂移、延迟、分割泄漏）？标准跟踪指标对跟踪器的排序与闭环成功率的排序是否一致？

- 为何能上顶会：HandoverSim 的 baseline 使用特权状态，GenH2R 的点云来自仿真器标签，DexH2R 的 Hard 模式又出现崩溃；本次检索没有找到在真实跟踪误差下测量闭环交接成功率的工作。如果能证明指标排序会被重排，这一结论会影响所有声称与机器人相关的手-物体跟踪论文。分析者用自动驾驶中的 Philion et al. CVPR 2020 作类比，该文献凭记忆引用，未核实。
- 方法草图：利用 DexYCB 的真实帧构建一个"感知状态版 HandoverSim"。在这些帧上运行 3 到 5 个现成跟踪器（例如 FoundationPose 加 SAM2，HaMeR 或 WiLoR），用 z-buffer 合成机械爪遮挡。仿真中物理仍按真值运行，但策略看到的是按跟踪位姿渲染并加入实测延迟的点云。对照组包括真值、按 RMS 匹配的高斯噪声和纯延迟偏移。再用 8 到 12 个跟踪器变体计算 Kendall tau，并拟合一个与任务挂钩的指标。
- 最小实验：两个开源策略（handover-sim2real、GenH2R）乘以 4 种观测条件乘以 3 个跟踪器，在 HandoverSim s0 上评估，再做秩相关研究。终止条件是：若 tau 高于约 0.9，且高斯噪声能够复现成功率损失，就停止或转向研究问题 2。
- 数据与硬件：DexYCB（约 100 GB，大小未核实）、HandoverSim（PyBullet，主要吃 CPU）、一块 24 GB GPU、一台消费级 RGB-D 相机；可选借用 Franka 或 UR 机械臂。
- 风险：视角不一致；"噪声当然有害"的质疑；给予者是非反应式回放；HandoverSim、GenH2R、DexH2R 的原作团队可能抢先；只有仿真证据的工作在 CoRL 上说服力偏弱。
- 目标会议：ICCV、CVPR、CoRL、ICRA、RA-L。

研究问题 2：跟踪器应当向策略输出点估计，还是带有校准不确定性和逐实体有效性标签（新测得、外推或保持、由接触推断）的状态？用学习得到的真实误差模型训练策略，或用策略感知损失微调跟踪器，能否找回成功率的损失？

- 为何能上顶会：腿式机器人和模仿学习中已有学习式噪声模型和校准干预的先例，但学习式交接策略中尚无工作把跟踪不确定性作为输入；该问题的答案可以迁移到示范采集、遥操作和数字孪生。
- 方法草图：用 GRU 拟合各跟踪器的时序误差模型，比较五种观测设置（真值、高斯随机化、学习误差、学习误差加有效性与不确定性通道、再加策略感知损失微调的跟踪器），用 split conformal 包装不确定性，并做打乱不确定性通道的消融。
- 最小实验：在 HandoverSim s0 和 s1 上进行五种设置的对比，留出一个跟踪器，每种设置 3 个种子。成文门槛是：加入有效性与不确定性通道的设置至少能找回真值与感知状态之间一半的差距，并且优于高斯随机化的幅度超过种子间方差。
- 数据与硬件：与研究问题 1 相同，另需数天的多核 CPU 和每种设置一块 GPU 的 RL 微调算力，具体成本未核实；投 CoRL 或 RSS 强烈建议借一台机械臂。
- 风险：高斯随机化可能已经填平差距；策略可能忽略新增通道；有限差分估计噪声大、计算成本高；没有真实机器人实验时，现实的下限是 ICRA 或 RA-L；容易被资源更多的团队快速跟进。
- 目标会议：CoRL、RSS、ICRA、RA-L、T-RO。

小实验室做不到的部分：在仿真中与 Motus、ME-Dex-1.0、GigaBrain-0.7 这类预训练大模型竞争；在 ALOHA 或 Cobot Magic 上做大规模真实评估；处理 BiCoord 和 DuoBench 报告的真实长时程耦合问题；采集 DexH2R 规模的数据（4,282 次试验，39 名参与者）；开展需要伦理审批的人类受试者研究。

论文资产（次要）：作用较小。measured/held/constrained 诚实标签可以作为研究问题 2 中有效性标签的原型；30 fps 因果链可提供实测的延迟与抖动；ArUco 标记物体可以低成本地核查物体跟踪误差。但 28 段单人录制中没有交接、机器人或手部真值，不能用作基准；Unity 孪生帮助不大，因为现有交接工具链基于 PyBullet。

## 写入报告的要点

经过核查后仍然成立的最强表述是：交接与协同策略在仿真真值状态上训练和评分，一旦状态必须来自真实跟踪器、且处在相互遮挡之下，性能就会大幅下降，而至今没有人在真实跟踪误差下测量过闭环交接成功率。最有力的证据是 DexH2R（ICCV 2025）从 Easy 到 Hard 的下降——DP 从 39.4% 到 8.3%，DP3 从 66.3% 到 27.1%——作者明确归因于遮挡；同时 HandoverSim 的 baseline 直接使用真值的手和物体状态。主要反对意见是，臂间协同在仿真中已基本饱和（Motus 在 RoboTwin 2.0 随机化设置下达到 87.02%，排行榜上 Handover Mic 接近 100），所以原始表述中的策略侧论断已经过时，artifact 视角据此以 3 分驳倒了原表述。最值得做的研究问题是：标准跟踪指标（MPJPE、ADD-S）对跟踪器的排序是否与闭环交接成功率一致，以及应当用什么与任务挂钩的指标来替代。合适的投稿去向是 ICCV 或 CVPR（以指标重排为卖点），或者在借到真实机械臂后投 CoRL 或 ICRA。
