# v2: genuinely live pipeline

v1 (git tag `v1-thesis`, all pre-existing folders) runs every stage from
the pinned recording; its real-time phase plays the bag back at recorded
pacing as a live-camera stand-in. v2 makes the chain live end to end:

    sensor (or bag) -> capture broker -> [A] person  \
                                      -> [B] object  -> merger -> Unity

with two additions over v1's real-time phase:

1. A capture broker owns the single device (live camera or bag playback)
   and publishes aligned color+depth frames to a shared-memory ring
   (PSF1), because two processes cannot both open one physical camera.
2. The merger runs a timestamp-paired delay buffer (thesis 8.3.1 +
   8.3.3): output renders at capture time minus a fixed, declared delay
   of two frame intervals (66.7 ms at 30 fps); short gaps are bridged by interpolation
   between measured samples and flagged; long gaps hold-last exactly as
   v1; re-acquisition blends instead of snapping. Packet PSI2 carries
   the measured/interpolated flags; Unity applies numbers, never creates
   them.

v1 code is never edited. v2 modules import the proven v1 modules in
place (same sys.path pattern v1 uses). The A/B independence policy is
preserved: v2/person imports only A-side modules, v2/object only B-side;
the frame ring is transport infrastructure below the independence
boundary, like /dev/shm and pyrealsense2 themselves.

Style rule for all v2 artifacts: professional plain text only. No
emojis, icons, or decorative Unicode in code, comments, logs, commit
messages, or docs. Markers: PASS / FAIL, OK / ERROR / WARNING,
[x] / [ ] checklists. ASCII punctuation only.

## Running it

    # full stack on the pinned recording (the camera-free test path)
    python v2/integration/run_v2.py --source bag --dump
    python v2/integration/validate_v2.py     # 21 checks; needs flags-off dumps in v2/output
    python v2/integration/plot_v2.py         # BEFORE any Unity run

    # live session (camera connected; scene re-calibrated at startup)
    python v2/integration/run_v2.py --source live --calibrate \
        --record v2/output/live_session.bag --dump

    # watch the sensor view of any running session (read-only ring
    # consumer; never opens the camera, attach/detach at any time)
    python v2/common/ring_viewer.py

The output delay is fixed and declared: --delay-frames 2 (66.7 ms).
Measured on the pinned recording: at 1 frame, about 7 percent of ticks
miss their future bracket (person sample availability lag approaches
the frame interval); at 2 frames, mid-run holds vanish (30 held person
ticks total, warm-up and tail only). Thesis 8.3.3 sanctions 1-2 frames.

## Unity

Start the stack (either command above), then press Play in the Unity
project (Unity/, scene SampleScene or rig). IntegratedSceneReceiverV2
bootstraps automatically when /dev/shm/integrated_scene_v2 and
/dev/shm/aruco_scene exist; the v1 receiver stays dormant because
/dev/shm/integrated_scene is never created by the v2 stack.

Colors: normal = measured or routinely resampled; RED = held / not
measured (v1 meaning, unchanged: red joint spheres, red cube); AMBER =
a real dropout crossed by interpolation (bridge) or the ramp back after
a long occlusion (blend): amber cube/plate tint and an amber pelvis
sphere. Unity's .meta file for the new script is generated on first
editor open.

## Camera night checklist (M6, user runs in order)

1. Plug the D435 into a USB 3.x port. Probe:
   rs-enumerate-devices | head. The broker prints the negotiated
   profile and exits loudly on a USB2 downgrade.
2. Broker alone, 10 s:
   python v2/broker/capture_broker.py --source live --max-frames 300
   Expect ~30 fps sustained and inter-frame jitter stats printed.
3. Place the markers: wall id 0 plumb on the wall, desk id 2 flat on
   the desk, cube id 1 resting on the desk (or plan --cube-size 0.07).
   Calibration rehearsal:
   python v2/integration/run_v2.py --source live --calibrate \
       --cube-size 0.07 --max-frames 300
   Inspect the printed static stability (v1 envelope: sub-mm /
   sub-0.2 deg) and the seed deviation (needs only < ~10 deg).
4. Full session with evidence:
   python v2/integration/run_v2.py --source live --calibrate \
       --cube-size 0.07 --record v2/output/live_$(date +%Y%m%d).bag \
       --dump
   Then plot_v2.py, then Unity (colors above). The recorded bag makes
   the whole session re-analyzable offline.
5. Deliberately cover the cube marker with a hand: short covers show
   amber (bridged), long covers show red then an amber ramp on
   reacquisition; the same events must reproduce from the recorded bag.

Run instructions grow here per milestone. Every number in this file
must come from a pinned validator or profile run; none are invented.
