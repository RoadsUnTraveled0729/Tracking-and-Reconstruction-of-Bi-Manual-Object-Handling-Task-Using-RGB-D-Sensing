# Recordings archive decisions

Decision log for the recordings bank (recordings/) and its mirror in
eval/recordings_archive/. Earlier archive decisions B-004 and B-005
(2026-09-23) are quoted in README.md; this file starts at RA-001.

ID: RA-001
Status: SETTLED
Decision: Move the recordings bank from /home/luo/Desktop/ENSC498/recordings into the repository at recordings/, leave a symlink at the old path, git-ignore it, and make the two deck bank scripts resolve it from their own location.
Why: Author decision 2026-10-05/06: the repository must be self-contained, while the 27 GB of .bag files stay local and are never pushed. Both folders are on the same filesystem (/dev/nvme2n1p3), so mv is a rename: no bytes copied, inodes and mtimes unchanged. The symlink keeps every recorded absolute path (logs, meta, manifests, docs, v3 configs) resolving without rewriting provenance, which the standing rule forbids.
Alternatives: Copy instead of move (rejected: doubles 27 GB and leaves two live copies to drift). Rewrite every recorded path to the new location (rejected: standing rule, recorded absolute paths stay as written). Git LFS or pushing the bags (rejected: author decision, bank stays local). Unanchored "recordings/" ignore pattern (rejected in favour of "/recordings/": the anchored form cannot hide a future subfolder named recordings elsewhere in the tree; no such folder exists today).
Evidence: lsof +D on the old path was empty before the move. A listing of all 64 entries (relative path, size, mtime, inode, type, symlink target) taken before and after the move is identical (diff empty). The three legacy symlinks resolve through both paths. git check-ignore reports .gitignore:3:/recordings/ for recordings/index.json. Path edits: presentation/defense_2026/anim/bank_kinematics.py and bank_axes_kinematics.py now set BANK = ROOT / 'recordings' (ROOT derived from __file__); an import check resolves BANK to /home/luo/Desktop/bimanual-tracking/recordings and finds all four page bags in each. raw_task_context.py reads Video/ and eval/recordings_archive/index.json only, so it needed no edit. v3/configs/clean_windows.json is left absolute: v3/bench/sweep_pose.py passes its "bag" value straight to BagSource with no root join, and every other loader uses only the stem. v3/dataset/phase5_side_by_side_manifest.json is an output written by v3/tools/side_by_side.py (provenance), not an input. v3 tests test_grade_clean.py and test_oracle.py pass (18 passed); eval/inspect/check_v1_overlay.py ran to completion on recordings/R4_desk_cube_labeled_path_accepted_20260825_070152.bag.
Side effect: the ENSC498 repository's .gitignore line "recordings/" matches directories only, so the symlink now shows as "?? recordings" (untracked) in that repository's git status instead of "!! recordings/" (ignored). ~/Desktop/ENSC498 is read-only apart from recordings/, so its .gitignore was not edited.
Reversibility: rm /home/luo/Desktop/ENSC498/recordings (the symlink only), then mv /home/luo/Desktop/bimanual-tracking/recordings /home/luo/Desktop/ENSC498/recordings, revert the two BANK lines and the .gitignore entry.
Review: Confirm the ENSC498 "?? recordings" status is acceptable, or allow a one-line ignore entry there (for example "recordings" without the slash). Confirm clean_windows.json should stay absolute rather than changing sweep_pose.py to resolve repo-relative bag paths.
Annotation 2026-10-06: the clean_windows.json part is superseded by RA-002 (paths made repository-relative, sweep_pose.py resolves them).

ID: RA-002
Status: SETTLED
Decision: Make the four bag paths in v3/configs/clean_windows.json repository-relative ("recordings/<name>.bag") and make v3/bench/sweep_pose.py bag_list resolve a relative window bag path against the repository root with the existing helper bench/paths.py repo_path (absolute paths are used as written).
Why: Milestone M5 of the self-containment plan (author goal 2026-10-06: a self-contained repository). clean_windows.json is a run-time input, not a provenance record, so its paths may change; the absolute form depended on the ENSC498 symlink, the relative form needs only the in-repo recordings/ folder. repo_path already implements this rule for the other v3 manifests (D-028 base_csv) and resolves from its own __file__, so the result does not depend on the working directory.
Alternatives: Keep the absolute paths through the symlink (rejected: depends on a path outside the repository, RA-001 Review question). A new root helper in sweep_pose.py (rejected: duplicates bench/paths.py). Resolving against v3/ (rejected: bench/paths.py rule is repository-relative, and recordings/ sits at the repository root).
Evidence: git grep clean_windows lists the readers; only sweep_pose.py (run mode, BagSource) uses the bag path to open a file. grade_clean.py, make_scenarios.py, teleport_rule_check.py, tools/side_by_side.py and tests/test_grade_clean.py use only Path(bag).stem, which is unchanged, so output names (npz, extraction CSVs) are unchanged. An import of sweep_pose.bag_list (env v3rt) resolves all four window bags to /home/luo/Desktop/bimanual-tracking/recordings/<name>.bag, each exists, and each sha256 equals the value recorded in clean_windows.json; repo_path called from /tmp gives the same root. sweep_pose.py --help runs. v3 tests test_grade_clean.py and test_oracle.py: 18 passed.
Reversibility: restore the four absolute paths in clean_windows.json (git revert); the repo_path call leaves absolute paths untouched, so the code change may stay.
Review: Confirm that run-time configs may hold repository-relative bag paths while recorded provenance paths (meta.json, manifests, logs) stay absolute. The pinned bag in v3/configs/default.json (paths.bag, Video/recording_20260224_083945.bag under the New_SandBox name) was left absolute: it resolves inside the repository through the standing New_SandBox symlink and is outside this decision's scope.
